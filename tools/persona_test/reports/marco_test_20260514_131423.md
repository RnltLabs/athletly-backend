## Recommendations

1. **Enforce sync_garmin_data + get_activities at the start of EVERY turn where the user mentions a fresh run.** Turn 4 ("war heute laufen") should have triggered both. The STRICT rule appears to be ignored after the first turn of a session.
2. **Make the critic agent blocking, not advisory.** Four violations of `no_fabricated_stats` across the session, all shipped to the user.
3. **Add a "do not infer threshold from training pace" rule.** Coach assumed 5:30/km = threshold for Marco. For a beginner running everything at 5:30-6:00, this is structurally wrong. Coach should either run a get_activity_details + HR analysis OR recommend a 5k time trial / cooper test.
4. **Add a "recovery-gates-intensity" rule.** If recovery alerts include `sleep_critical` or HRV-trend-negative, the coach must downgrade or postpone Tempo/Interval sessions. Today Marco got 5:00-5:15/km Tempo prescription on a sleep-critical week.
5. **Enforce a length cap on Turn 1.** First message of a session should never exceed ~120 words. Coach failed this badly with a 280-word opener for an explicitly impatient persona.
6. **Re-fetch alerts when referencing alert content.** Coach kept quoting "HRV 30 ms, Body Battery 50-65" from memory rather than re-grounding. Even a redundant get_recovery_alerts call would have made these statements legitimate.

## Top 3 Findings

1. **Holistic instinct is strong but ungrounded** - coach correctly attributed tiredness to recovery (excellent) but quoted numbers from memory, not fresh tool calls. Critic flagged this repeatedly but it was ignored.
2. **Threshold-pace hallucination** - "Schwellenpace 5:30/km" was invented in Turn 3 and propagated through Turn 6's HR Zone 2 calculation and Turn 7's fitness assessment. For a persona explicitly defined as "threshold UNKNOWN", this is a structural failure.
